**نقطة العمل التالية داخل نفس الإدارة:** مراجعة حالات إزالة وصول الموظف وتغيير حالته ودمج إبطال رموز التحديث بطريقة لا تكرر callable الموجود، ثم معاملة حواجز الجوائز/المعرّفات الخادمية كقضايا تفعيل محجوبة مع الحفاظ على واجهاتها الحالية. لا رجوع لاسترجاع A/B/C.


### متابعة نفس بطاقة الفريق: إبطال الجلسات في التعديل والحذف — 2026-11-23

- جرد 01 أثبت أن تغيير حالة الموظف عبر زر «تعديل» إلى موقوف/معطّل، أو إزالة وصوله، كان يغيّر Firestore دون محاولة إبطال رموز التحديث. جرى استكمال **الوظائف الموجودة نفسها** دون إنشاء callable جديد.
- عند تعديل الحالة إلى `temporarily_stopped` أو `disabled` يستدعي عميل الإدارة الثانوي `revokeScopedSuspendedMemberSessions` القائم. عند فشل Auth تبقى صلاحية الموظف معطّلة، تظهر نتيجة جزئية وزر إعادة المحاولة.
- زر «إزالة وصول الإدارة» يتسلسل: تعليق الموظف إذا كان نشطاً → إبطال رموز التحديث عبر callable الموجود → حذف سجل الإدارة وبوابة الهاتف بالمعاملة الإدارية القائمة. عند الفشل يتوقف التسلسل دون حذف حساب DEDA أو Firebase Auth.
- الحارس الخادمي في `removeScopedAdminMemberAccess` يمنع حذف موظف ما زال نشطاً أو حالته غير معروفة؛ ومسار إبطال رموز التحديث يسمح بالمعطّل أيضاً، لا بالمستخدم العادي أو المدير العام. يبقى إبطال ID tokens فورياً غير مضمون؛ قواعد الصلاحية تمنع استعمال الدور الموقوف.
- تعديل المصدر **على الفرع المعزول فقط**؛ لا Firebase نشر ولا Play ولا تعديل القواعد الحقيقية أو الكود المنشور؛ لا إعلان نجاح حتى CI.
