## ما تغير فعلياً داخل التطبيق الأصلي
1. **`lib/main.dart`**: استبدال بطاقة «مطاعم» ببطاقة «المتصدرون» في واجهة DEDA **للقياسين العمودي والأفقي (الهاتف والتابلت)**. عند الضغط، تفتح شاشة الدوري الرسمية `DedaWeeklyLeaderboardSafeScreen` عن طريق `DedaWeeklyAccountViewGate` التي تثبت الحساب ورمز Firebase Auth عند الدخول وتلغي الثقة بالبيانات عند تبديل الحساب أو تسجيل الخروج.
2. إبقاء بطاقة المهام اليومية موجودة، وربط زر الوصول للمهام داخل الدوري بنفس صفحة `DedaDailyTasksPage` الأصلية، من دون منح نقاط أو تحريك رصيد عند الفتح.
3. **`lib/deda_weekly_verified_standings_bridge.dart`**: عميل Firebase Functions يطلب `dedaWeeklyVerifiedStandingsV1` فقط، مع إعادة التحقق من هوية المستخدم قبل وبعد انتظار الشبكة. لا يجمع الرصيد من `SharedPreferences` ولا يقرأ درجات التجربة أو يحقن أسماء ومراكز. عند غياب نتيجة معتمدة تبقى الشاشة بلا ترتيب مؤكد.

## ما تغير في خادم Firebase (غير منشور)
4. **`functions/deda_weekly_verified_standings_reader_core.js`**: قارئ نتائج أسبوعية للمركزين «الأسبوع الحالي والسابق» من مستند واحد **خادمي وموقع HMAC** `deda_weekly_approved_publication/active`، بعد التأكد من UID حقيقي وPIN-binding خادمي وحساب DEDA ثابت وغير معطل. يقارن التوقيع والمدة وتوقيت الأسبوع ودرجات XP وعدد مهام اليوم وترتيب أفضل عشرة، ويمنع التكرار والتلاعب بالمراكز والآيديات. الإغلاق 00:00–06:00 بتوقيت بغداد يرجع النقاط ثابتة؛ لا يمنح ماسات أو جوائز.
5. **`functions/deda_weekly_verified_standings_reader.js`** + `functions/index.js`: ربط Callable باسم القارئ، بإعداد `enforceAppCheck:true` وسرّ `DEDA_WEEKLY_VERIFIED_PUBLICATION_HMAC_KEY`. لا ينشر Firebase، ولا يصرف 150/100/50/10 ماسات، ولا يعدل نقاط المستوى أو XP أو ملف الإدارة.
6. **فحوص آلية**: 12 فحصاً برمجياً للقارئ، و5 اختبارات Auth/Firestore على المحاكيات الحقيقية وقواعد Firestore الأصلية. Workflow منفصل يتضمن فحص الكود وFlutter Analyzer والواجهة الرئيسية في الهاتف والتابلت. كلها **مجهزة**؛ لا نُعلن نجاح GitHub Actions قبل التحقق من run ناجح للنسخة النهائية.
