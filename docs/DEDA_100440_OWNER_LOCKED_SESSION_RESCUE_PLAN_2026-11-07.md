## القرارات الثابتة من المدير العام
1. حماية النسخة `100440` كاملة وإضافاتها وحفظها كمرجع، بلا تغيير أو تراجع.
2. كود واحد **مستقل ومتكامل** `deda_session_recovery_coordinator.dart` يرتبط **بحارس الجلسة الموجود**، لا يستبدله ولا ينشئ حارساً موازياً.
3. الحفاظ على سلوك الأكواد القديمة وجميع أقسام التطبيق: المعرف، الأصدقاء، الإدارة، Google، الهدايا، الدوري، الماسات، الملف، الاسترجاع وبقية الوظائف.
4. استعادة التحقق من **هوية الجلسة الحالية المثبتة**، ومحاولة الإنعاش الآمن والقراءة مجدداً عند تعطل الشبكة، بلا تسجيل خروج أو إنشاء UID أو حساب بديل.
5. الإدارة: **لا تجاوز للصلاحيات**. خطأ الشبكة لا يصبح حكماً دائماً برفض الصلاحية؛ تعرض حالة الاتصال أو إعادة التحقق إن كانت الجلسة نفسها ثابتة. الدخول لا يتاح إلا بعد الدليل الخادمي الأصلي.
6. Google: العمل فقط بعد إثبات ملكية الحساب الأصلي وUID الأصلي. لا ربط أو تغيير بيانات بمجرّد الاتصال بشبكة أو اختيار Google.
7. إشعار الأقسام المتأثرة بجاهزية الحساب المشتركة بعد نجاح الإثبات؛ إلغاء طلبات التحقق المكررة وتحسين السلاسة؛ لا تحديثات متواصلة أو حلقات محاولات.
8. الاختبار على APK موقّع واحد لاحقاً بعد فحوص التكامل وموافقة صاحب المشروع، **دون نشر Google Play**.
9. **صاحب المشروع يراجع كل خطوة**؛ لا دمج ولا بناء ولا نشر ولا تفعيل Firebase تلقائياً بين نقاط المراجعة. أي تعارض جديد يُبلغ بوضوح قبل الاستمرار.

## التصميم المبدئي المتفق عليه (لا يساوي إثبات نجاح التنفيذ)
- المنقذ يراقب **نفس** `FirebaseAuth.currentUser` و`DedaAuthRuntime` و`DedaSessionTransitionGate`، ويحفظ لحظة الفحص UID + epoch/accountKey. يُرفض أي رد متأخر بعد تبديل UID أو الحساب.
- يُفرق بين الحالات: `ready`، `checking`، `transientNetworkFailure`، `requiresOwnerProof`، `permissionDenied`، `uidMismatch`، `signedOut`. لا يحوّل فشل القراءة إلى صلاحية أو هوية صحيحة.
- لا يطلب نسخة جديدة من جلسة Firebase أو UID عند فقدان الاتصال؛ يمكن تجربة تجديد token لنفس Firebase user فقط عند الحاجة وبعد التحقق من ثباته. لا تتغير كلمات السر أو روابط Google أو أدلة ملكية البيانات في الخلفية.
- يُنفّذ `single-flight` للقراءة والتحقق لنفس UID مع مهلة ومحاولة محدودة وتأخير محسوب لفشل الشبكة العابر. لا يكرر نداءات التحميل عند كل إعادة بناء للواجهة.
- بعد الإثبات الخادمي الجديد لذات UID/accountKey، تُحدّث الأقسام ذات الجلسة نفسها دون إعادة المصادقة لكل قسم. الأصدقاء والمعرف يُقرآن بالمسارات الأصلية الآمنة.
- يظل سجل `admin_entry_access` و`admins` وصلاحيات Firestore هو صاحب القرار. حالة «جارٍ إعادة الاتصال» ليست إذناً بعرض لوحة الإدارة أو تشغيلها.
- إن تعذر إثبات الملكية أو تغير UID، يُوقف الإنقاذ ويعرض تمييزاً واضحاً بين انقطاع الاتصال وحاجة المستخدم لتأكيد الحساب أو خطأ صلاحيات حقيقي.

## المرحلة 1 — فحص وتشخيص وتثبيت المسار (الحالية)
**مصادر موثقة تمت مراجعتها قراءة فقط بتاريخ 2026-11-07:**
- `lib/deda_auth_session_runtime.dart`: `DedaAuthRuntime.capture/checkSnapshot/run/afterSuccess` وحارس العمليات المتزامنة.
- `lib/deda_session_transition_gate.dart`: تغيير auth ليس مسموحاً تلقائياً بالخلفية، وحارس واحد يمنع التداخل؛ لا يُسمح بتجاوز الحارس لتحقيق استجابة شكلية.
- `lib/deda_100431_linked_owner_session_policy.dart`: `verified` يطلب 4 إثباتات خادمية مع تطابق UID وحالة المستخدم غير المجهولة؛ يلتقط الأخطاء ويرد `false` دون تمييز سبب التعثر.
- `lib/deda_backend.dart`: `currentDedaAccountCanSeeAdminEntry` يفشل إلى `false` عند الاستثناء، ما يخفي المدخل؛ `_ensureOwnerSessionForAccountKey` يحمي UID المرتبط ويرفض تبديله آلياً.
- `lib/main.dart`: `_refreshAdminEntryVisibility` ينفذ عند فتح صفحة الإعدادات ويُخفي مدخل الإدارة عند فشل الاستجابة؛ لا يوجد في هذا المسار إشعار مشترك جاهز من تحقق الجلسة.
- `lib/deda_step1_google_settings_link_100439.dart`: قبل اختيار حساب Google يجب إثبات ملكية حساب DEDA الأصلي؛ الخطأ العام يخفي النوع المحدد من فشل الإثبات.
- `lib/deda_pin_auth.dart`: `restoreTrustedSessionForAccountKey` يعيد استخدام UID الأصلي ولا يقبل هوية غير موثقة في النسخة التجريبية.
- `lib/deda_social_service.dart`: إعداد جلسة الأصدقاء مرتبط بهوية المشاركة عبر `ensureLocationShareIdentity` وFirebaseAuth؛ لا يجوز إرجاع صفر دائم عند فشل الجلسة.
- سجل بناء 100440 `42340149961` نجح في CI؛ ليست لدينا بعد سجلات Android runtime من الهاتف تثبت السبب الجذري.

**النتيجة المثبتة من الكود:** خطأ الشبكة / الجلسة المفقودة / منع الصلاحيات يمكن أن تؤدي في بعض المسارات إلى «false/إخفاء» متشابه؛ هذا **موقع محتمل لإصلاح التشخيص والتعافي** ولا يثبت سبب عطل هاتف صاحب المشروع بشكل قاطع.
