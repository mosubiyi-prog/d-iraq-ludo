- استعمال إعداد الخدمة الموثوق الموجود سلفاً deda_stage2_runtime_identity.js (enforceAppCheck: true، هوية تشغيل مخصصة)، مع وجود App Check وFirebase Callable auth UID متحققين من إطار Firebase.
- تدقيق Firebase ID token بتوقيع وصلاحية الخادم، مع checkRevoked=true ورفض اختلاف UID إطار Callable عن UID الرمز. لا يعتمد على UID أو رمز PIN أو رقم هاتف يدخله العميل كسلطة إثبات.
- حدّ محاولات ذري مع Firestore Transaction على deda_100441_uid_preflight_rate_limits، لكل accountKey bucket مشتق من HMAC-SHA256 بمفتاح خادمي منفصل لا يُحفظ بالمستودع. لا يخزن رقم هاتف ولا PIN ولا UID في سجل الحد.
- أقصى حد 5 محاولات/ساعة و12/يوم في المرشح. ما لم يُعتمد المفتاح الخادمي وIAM والاختبارات الحية يُمنع التفعيل.
- يستهلك المحاولة قبل أي قراءة لبيانات الحساب، ولا يمكن تجاوز الحد بمجرد تغيير UID أو الهاتف. البيانات المعطوبة أو الساعة المتراجعة تؤدي إلى منع العملية.
- يستدعي قارئ Firebase Admin السابق للمرحلة الثالثة ويفحص بيانات الدليل والآيدي الأصلي والملف الاجتماعي دون كتابة أو إصلاحها.
- يرجع حالة عامة واحدة status=review_required للحالات المقبولة للفحص سواء تطابقت السجلات أو انقسمت أو كانت غير موجودة، ويعيد رسالة رفض عامة للطلبات غير الموثوقة والحدود والأخطاء. لا يرسل UID أو originalId أو accountKey أو رصيد أو امتياز أو تشخيص حساس للمستخدم.
