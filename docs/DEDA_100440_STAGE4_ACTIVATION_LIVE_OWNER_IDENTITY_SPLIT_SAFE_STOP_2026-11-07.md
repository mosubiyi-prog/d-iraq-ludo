# DEDA 100440 — مراجعة تفعيل المنقذ: تعارض هوية خادمي، وقف آمن

**التاريخ:** 7 تشرين الثاني/نوفمبر 2026 (بغداد).  
**أمر المدير العام:** «تمام هسة تكدر تباشر بطمئنان تام احسنت».  
**العمل المنجز:** إثبات جاهزية التفعيل بحساب المدير الأصلي على Firebase الحقيقي *قراءة فقط* بعد نجاح 34 اختباراً على مصدر التطبيق.  
**الحالة:** **BLOCK / SAFE STOP** للتفعيل الشامل؛ لم يحدث نشر Firebase أو ربط حساب أو تغيير UID أو بناء APK.

## أدلة الفحص الحي
- مصدر السجل: [GitHub Actions 42410941332](https://github.com/mosubiyi-prog/d-iraq-ludo/actions/runs/42410941332)، تأكيد أعمق لنفس المدخل الأصلي الذي استُخدم سابقاً في فحص محفظة المدير العام.
- فحص حماية نسخة 100440: `PASS_100440_PROTECTED_SOURCE_UNCHANGED_NO_DEPLOY`.
- التوجيه الشخصي الأصلي `deda_share_ids/{originalId}`: موجود، نشط، نوعه personal، ورابط `ownerUid` محفوظ.
- `users/{originalUid}`: موجود، ويحمل `sharePersonalId` الأصلي وحساب الهاتف.
- `deda_sessions/{originalUid}`: **غير موجود**.
- `deda_account_directory/{accountKey}`: موجود لكن `createdUid` **لا يساوي** `originalUid`.
- UID الثاني الموجود في directory: له مستند `users/{secondUid}` بنفس `accountKey`، لكن **لا يدّعي الآيدي الأصلي**؛ لا توجد له جلسة `deda_sessions` أيضاً. **لا يجوز دمجه تلقائياً أو حذف بياناته.**
- الحسابان مسجلان في Firebase Auth، لكن **لا بريد دخول** لهما؛ لا دليل على تسجيل دخول أصلي بالبريد/الرمز أو Google.
- مدخل `admin_entry_access/{accountKey}` موجود ومفعّل؛ **وثيقة الإدارة لا توجد على `originalUid`**، وهو ما يصحّح افتراضاً سابقاً بأن شرط منع administrator تحت UID الأصلي هو العائق الأساسي. أي إدارة منفصلة تحتاج فحصها بحارسها الخاص.
- مصدر `DEDA_STEP2_SPARK_LINKED_UID_READ_ONLY=true` يشترط `signInWithEmailAndPassword` ثم 4 سجلات خادم متطابقة: هذه الشروط **غير متحققة حالياً**. تشغيل العلم وحده لن يعيد الجلسة.
- الأعلام الجديدة لمنقذ الجلسة والأصدقاء مختبرة على محاكيات المصدر (`34/34`) ولا تعالج تلقائياً انقسام أصل الحساب في Firebase.

## تفسير نتيجة الجلسة
**السبب الخادمي المثبت لعدم صلاحية التفعيل:** الانقسام بين UID الأصلي المملوك للآيدي، وUID آخر في سجل دليل الرقم، مع فقدان مستندَي الجلسة وعدم وجود وسيلة دخول مربوطة بالـUID الأصلي. هذا **يثبت فشل شروط التفعيل الآمن حالياً** ولا يثبت أي UID تستخدمه نسخة الهاتف هذه اللحظة دون logcat أو فحص تطبيق الجهاز.

## قرار السلامة
1. **ممنوع تفعيل `DEDA_STEP2_SPARK_LINKED_UID_READ_ONLY` للجميع أو بناء APK يدّعي استرجاع الحساب** قبل تثبيت المالك الأصلي ومصالحة الدليل والجلسة.
2. ممنوع تحرير `deda_account_directory` أو إنشاء `deda_sessions` أو ربط بريد/Google أو نقل ماسات، أصدقاء، هدايا، أرصدة، إدارة أو تغيير UID على التخمين. يلزم إثبات PIN/حارس موثوق وسجل خادمي مصادق مع عملية محددة، قابلة للتدقيق/التراجع.
3. حساب الدليل الثاني يحتاج فحص مسؤولية منفصل: ليس بالضرورة حساباً خاطئاً أو غير مشروع. لا يُحذف ولا يُدمج لمجرد تعارض الرقم.
4. **لا يلزم فرع GitHub جديد أو نشر Firestore Rules واسع** لهذا الفحص. قد يلزم **معالج خادمي موجّه** يربط وسيلة دخول بنفس `originalUid` بعد تحقق المالك وحل تعارض `accountKey` في معاملة موثقة. حالة Cloud Functions للنظام السابق غير مثبتة كمنشورة؛ آخر deploy مؤكد فشل عند Cloud Build API/صلاحيات التفعيل يوم 5 نوفمبر 2026. يطلب أمر صريح قبل أي نشر/تصحيح Firebase.
5. بعد نجاح تصحيح الربط الخادمي (بتأكيد owner): فحص قراءة جديد يعيد `DIRECT_SPARK_OWNER_ACTIVATION_SAFE YES`، **ثم** تفعيل المنقذ في فرع نسخة فحص موقعة، وقياس الهاتف للأصدقاء والإدارة وGoogle والآيدي الرباعي والهدايا بدون Play.
