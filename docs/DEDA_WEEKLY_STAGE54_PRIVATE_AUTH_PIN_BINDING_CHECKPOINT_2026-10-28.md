## Stage54 actual isolated implementation
- `tools/app_stability/stage54/functions/index.js`: a **Functions v2 callable in a disposable demo Firebase project**, refuses to start unless Auth, Functions and Firestore emulator hosts, exact demo project, emulator-only flag and disposable QA HMAC key are present. No export from actual deployed `functions/index.js`.
- Server derives calling UID from `request.auth.uid` from the local callable and checks it exists as an *anonymous* Firebase Auth Emulator account via Admin `getAuth().getUser(uid)`. Caller **cannot supply a UID, device installId, XP, diamonds, coins, taskId or rank**. Only exact `{accountKey, pin}` is accepted, only as a local test challenge.
- Server-side Admin SDK Firestore transaction reads actual **legacy schema** `deda_credentials/{accountKey}`, `deda_account_directory/{accountKey}`, `deda_account_profiles/{accountKey}` from synthetic emulator records. Confirms active credential, active directory, matching profile and valid 6-digit PIN. Keeps raw PIN out of its private rate-limit and binding documents, output and intentional logs; uses timing-safe hash comparison.
- Same atomic transaction maintains `deda_stage54_private_pin_limits/{HMAC(accountKey)}`, blocking an account for 15 minutes after 5 wrong PINs even if a second caller UID tries; compares lockout before approving a correct PIN. This is a **QA prototype, not a production brute-force protection deployment**. It may allow targeted lockout abuse and needs security review before production.
- On a valid PIN, creates idempotent `deda_stage54_private_account_bindings/{authUid}`: a server-owned **HOLD ONLY** record linking that emulator UID to canonical accountKey, without any installId authority. Does not silently rebind an existing UID to a different account; supports distinct phone UIDs sharing same verified account. Does not migrate original UID data or authorize level points, XP, social coins, weekly XP, user diamonds, winner gifts or purchases.
- All successful responses have `awardState:HOLD_NO_GRANTS`, `productionReady:false`, `migrationApproved:false`, and all reward flags false. No user/account/PIN, ID, balance or wallet data returned.

4. **Stage54 only creates private HOLD identity bindings in local demo emulator**, no XP, leaderboard points or 150/100/50/10 real rewards. Existing weekly UI enhancements and 00:00–06:00 freeze/06:00 approved greeting remain not live-integrated.
5.
