# DEDA 100441 — النقطة 2، تصميم حارس إثبات الملكية المستقل (وقف آمن)

**التاريخ:** 2026-11-08 (العراق).  
**أمر المدير العام:** «اذا تشوف هاذا لحل مناسب وامن خسب دراستك للموضوع باشر بنفس الحذر».  
**الحالة:** أنجزنا سياسة مراجعة ملكية *منعزلة وغير منشورة* واختباراتها؛ لا يوجد إثبات مالك فعلي أو جلسة جديدة حتى الآن.

## السبب المؤكد
تشغيل [42418971509](https://github.com/mosubiyi-prog/d-iraq-ludo/actions/runs/42418971509) كشف انقسام الحساب بين ثلاث هويات Firebase مختلفة:
- A: مالك توجيه الآيدي الأصلي `deda_share_ids`.
- B: سجل إنشاء الرقم والرمز `deda_account_directory` / `deda_credentials`.
- C: الملف الاجتماعي وجلسة خادمية تاريخية `deda_social_profiles` / `deda_sessions`.
- النسخة 100441 على هاتف المالك أعطت `FirebaseAuth.currentUser=null`، أي لا توجد جلسة قابلة للاستخدام حالياً.
- الفحص الحي [42419638188](https://github.com/mosubiyi-prog/d-iraq-ludo/actions/runs/42419638188) أكد: لا مزامنة PIN لـFirebase Auth ولا بريد دخول مصطنع على السجل، والـUID الخاص بالدليل لا يساوي صاحب الآيدي الأصلي. **لم يُقرأ الرمز**.
- وجود جلسة Firestore تحت C لا يثبت وجود Firebase Auth session حالياً أو حقها في نقل ملكية الآيدي.

## سبب عدم الاكتفاء بالـPIN
- الرمز من **6 خانات** محدود الاحتمالات وقابل للتخمين؛ لا يسمح وحده بإصدار custom token أو اختيار A/B/C.
- `functions/deda_owner_pin_verify_private_v1.js` يرفض إثبات المالك إذا اختلف `createdUid` عن `ownerUid`، ويتطلب App Check وجلسة caller صالحة وrate limiter ومؤشر `pinSyncVersion=1`. الـcustom token من PIN وحده معطل في الإنتاج.
- كود تسجيل الدخول القديم `lib/deda_pin_auth.dart` يكتب PIN في وثيقة محاولة مصادقة بآلية Firestore قديمة؛ **لا نستخدمه هنا**، ولا ننقل PIN إلى logs/CI/ChatGPT، ولا ننسخ هذا النهج في خدمة جديدة.
- ربط Google وكلمة مرور Firebase للمستخدم الأصلي **غير مثبتين**، والجلسة على هاتف 100441 مفقودة. App Check وحده لا يثبت ملكية المستخدم، وصورة الشاشة أو الرقم وحدهما لا يكفيان.

## ما أضيف الآن (لا يعمل في الإنتاج)
- `functions/deda_100441_owner_split_identity_challenge_review_private_v1.js`: دوال *نقية* تحلل تناقض A/B/C دون كشف المعرفات؛ تطلب إثبات PIN موقّع داخلياً من خادم محدود المحاولات مع nonce حديث، ودليل **مستقل** صادر من مصدر موثوق يرتبط بالـUID الأصلي، ثم مراجعة منفصلة للملكيات والنسخ الاحتياطية والتراجع. **حتى مع اكتمال بيانات المحاكاة لا تصدر الدالة إذن دخول، UID أو token**؛ أقصى ناتج `CANDIDATE_FOR_SEPARATE_OWNER_REVIEW` مع `loginPermitted:false`.

- `.github/workflows/deda-100441-split-owner-independent-proof-private-qa-no-deploy-2026-11-08.yml`: فحوص Node 20 مع 31 اختباراً سابقاً؛ المصدر المحمي وFirebase لم يتغيرا، ولا مستخدمون أو رمز حقيقي داخل الاختبارات.
- إثبات GitHub Actions [42420337496](https://github.com/mosubiyi-prog/d-iraq-ludo/actions/runs/42420337496): **43/43 اختباراً ناجحاً**، `PASS_PROTECTED_100440_PRODUCTION_FUNCTIONS_AND_FIREBASE_UNCHANGED`، `PASS_PRIVATE_REVIEW_ONLY_ZERO_AUTH_TOKENS_WRITES_OR_DEPLOY`.

## بروتوكول التحقق المقترح قبل السماح بأي تنفيذ لاحق
1. **إثبات مستقل مسبق**: إن كان هناك هاتف أصلي آخر لا يزال يحمل جلسة Firebase لنفس `ownerUid=A` وقادراً على تنفيذ تحدي خادمي جديد بجهاز سبق توثيقه قبل الحادث، نتحقق منه أولاً، دون إنشاء جلسة جديدة على هاتف 100441. أو نستخدم مزوّد دخول سبق ربطه بنفس UID، **إن ثبت ذلك لا إن افترضناه**.
2. إن لم يوجد عامل موثوق مسبق، **يتوقف الاسترجاع الآلي**. نحتاج استرداداً يدوياً موثقاً يعتمد على إثبات مستقل من سجلات المؤسسة/المزوّد الأصلي، مع مراجعة منفصلة؛ أو إنشاء عامل مستقل موثوق ضمن إجراء استعادة يلتزم بسياسات الخصوصية والحساب، لا مجرد رسالة من المحادثة أو لقطة.
3. **PIN بعد العامل المستقل فقط**: تحدٍ خادمي جديد محدود المحاولات ومقيد بالحساب وجهاز الطلب والوقت، مع منع الإعادة والتسريب؛ لا إدخال PIN في GitHub أو ChatGPT، ولا استعمال وثائق `deda_auth_attempts` القديمة كبديل عن الحارس.
4. **مصالحات منفصلة بعد الموافقة**: نسخة احتياطية لسجلات A/B/C والتصاميم، ثم خطة معلنة لمعالجة `deda_account_directory` و`deda_share_ids` و`deda_social_profiles`؛ أي فعل تغييري منفصل متسلسل قابل للمراجعة والتراجع، دون نقل ملكيات الماسات والهدايا أو منح إدارة عبر هذا المسار.
5. **إثبات قبل تغيير الهاتف**: بعد المعالجة الخادمية الموثقة، ربط Auth **بنفس UID المعتمد**، تجربة الجهاز وفحص الأصدقاء والإدارة والآيدي المميز والعناصر المالية بشكل مستقل. لا يثبت رمز PIN وحده هذه الخطوة.

## العائق المتبقي الحقيقي
**غير معروف حتى الآن وجود عامل ملكية مستقل سبق توثيقه للحساب**. لا يُفترض أن الجهاز الحالي يملك جلسة Firebase (هو لا يملكها). فحص عنصر الثقة من جهاز أصلي آخر — إن وُجد — هو المعلومة العملية القادمة. إذا لم يوجد جهاز مصادق أو موفّر موثوق سابق، نحتاج إجراء استعادة يدوية مستقل؛ أي حل «فوري» مبني على PIN وحده سيكون غير آمن.

## القيود والنتيجة
- لا `firebase deploy`، لا تعديل Firestore/Auth/Rules/Cloud Functions المنشورة، ولا تسجيل دخول فعلي أو PIN أو إصدار token أو تشغيل حساب جديد.
- لا APK/AAB أو Play؛ النسختان 100440 و100441 وبيانات المستخدمين والأصدقاء والماسات والهدايا والإدارة والآيدي المميز محفوظة.
- **STOP:** حارس الإثبات المستقل جاهز كمصدر خاص واختبارات أمنية، لكنه ليس خدمة تشغيل أو مصادقة مكتملة. يحتاج تحديد وسيلة إثبات مستقلة قابلة للتحقق والموافقة على بروتوكولها قبل أي نشر أو مصالحة للـUID.
