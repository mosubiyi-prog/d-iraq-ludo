# ربط تنظيم المصادقة بمصدر 100380

نقطة الرجوع: `checkpoint-stability-before-auth-runtime-2026-10-24` عند `39c64c74202216ba6b1cbf759cf96bef02a59905`.

`--auth-runtime` يولد overlay من المصدر المحفوظ ذي البصمات، ويقبل تركيب القياس والحفظ السابقين دون تغيير الأرشيف. العلم `DEDA_STABILITY_AUTH_RUNTIME` افتراضي false؛ هذا تطوير وفحص، وليس تفعيل إنتاج أو APK جاهزة.

## ما ربط فعلياً في المصدر الناتج

- DedaPinAuth: إنشاء الحساب والدخول والاستعادة الموثوقة وطلب الاسترجاع وفحص وجود الحساب وتوثيق الجهاز والخروج؛ عمليات SDK تدخل lane واحدة دون تحريرها عند مهلة الواجهة. تبقى المهلة الأصلية للفرع المعطل.
- Backend: تجهيز المستخدم العام/جلسة المالك، دخول الإدارة وتفعيل الدعوة وتغيير كلمة المرور والخروج. فحص أيقونة الإدارة ومطابقة الهاتف وself-heal وكاش الملف والإشعارات والتدقيق تدخل نفس السياق؛ إثبات الخادم والأدوار الأصلية محفوظة.
- main: إنشاء الحساب وPIN ورمز الاسترجاع مع حفظ تفضيلات الحساب داخل نفس التسلسل؛ load/saveLogin/logout منظمة أيضاً. لا تمنح التفضيلات دوراً أو ملكية.
- admin_pages: دخول الإدارة وحفظ الهوية وقراءة الملف ومطابقة admin_entry_access والخروج عند رفضها داخل حجز واحد. يبقى حوار كلمة المرور خارجه؛ يعاد فحص UID/نوع/epoch الأصلي قبل الحفظ أو خروج الإلغاء أو فتح لوحة الإدارة. التفعيل ومطابقة الهاتف أيضاً داخل حجز واحد.

الحراسة حول awaits تمنع الأثر التالي عند فقد نية الشاشة أو تغير SDK، مع epoch لتبدلات A→B→A حتى عبر حالة الخروج. المساعدات الموروثة تستعمل التصريح الحالي ولا تعيد دخول gate. SDK mutation خارج lane مرفوضة. انتهاء الانتظار لا يلغي طلب SDK أو كتابة سبق إرسالها ولا يعيدهما تلقائياً، ولا ينفذ خروج تصحيحي عام.

`sessionInspection` يسمح للقسم النشط بفحص بوابة مدير قائم، لكن لا يسمح بإنهاء جلسته أو استبدالها. وجود جلسة أو نجاح قفل محلي ليس تخويلاً. النظام لا يبدل حسابات Firebase الحية أثناء التطوير ولا يغير قواعدها.

## الفحص والحدود

هناك فحوص منطق للتنافس/المهلة/الهوية، وفحوص تستدعي مداخل PinAuth/Backend/Preferences **الفعلية المستعادة** أثناء حجز lane للتحقق من رفض التجاوز قبل أي SDK/تفضيلات. فحص CI يجمّع المصدر المركب كله ويشغل اختبارات الحساب/الملكية/الواجهة السابقة.

هذه اختبارات مصدر ومحاكاة. لم يُفحص هذا الربط بعد مع واجهة ديدا على هاتفين أو SDK Android ضمن مساراته الجديدة، ولم يُفعّل للمستخدمين. واجهات busy/timeout في بقية مواضع الخروج والأقسام، والانتهاء المحلي الجزئي عند فشل التفضيلات، واستمرار أعمال البيانات الخلفية بعد اختيار الحساب تحتاج فحوص تكامل؛ لا تنسب إليها حماية كاملة من هذه الدفعة. لا معاملات نقل أرصدة أو مصالحة مالية أو نشر قواعد هنا.

يلزم قبل التفعيل اختبار الربط نفسه مع SDK/الخادم، ومعالجة أي خطأ مصدر تكشفه CI، ثم قبول التطبيق كاملاً وبيانات الحساب على هاتفين. سجل CURRENT هو المرجع الأحدث؛ لا تعِد native PIN السابق كبديل لفحص الربط الجديد.
