## ما أضيف

أضيف قارئ ومخزن مستقلان في `lib/deda_legacy_purchase_evidence.dart` دون تعديل Checkout أو المحفظة أو أسعارها. يقرأ القارئ المفاتيح الأصلية للإطارات13 وinventory الحساب فقط. SharedPreferences.get يحفظ الأنواع غير المتوقعة بما فيها bool/int/double finite/list<String>، والغياب null؛ النص الخام داخل قيمة inventory يبقى كما هو ولو تالفاً. لا قراءة عامة لكل تفضيلات الجهاز أو PIN/كلمة مرور، ولا write/remove/clear/checkout أو تصحيح تلقائي. نقص نتيجة القراءة أو تبدل نية الحساب/جيل SDK يرفض النتيجة؛ الحجم المفرط/نوع غير مدعوم يرفض الرفع دون تغيير المصدر.

النسخة `legacy-purchase-evidence` محفوظة في namespace جديد `deda_purchase_evidence/<account>/captures/<captureId>`. حقول records هي originalId وprogressCaptureId وlocalSnapshot (JSON يحفظ الأنواع). يعاد استخدام IO القائم للكتابة الثابتة غير القابلة للاستبدال مع قراءة خادمية مثبتة. الرد الغامض يحتاج أن يحتفظ المستدعي بنفس captureId/payload؛ لا retry تلقائي أو relabel إلى جهاز آخر. القراءة من UID/install جديدين لنفس حساب PIN تحتفظ بأصل النسخة القديم. حفظ جديد يحتاج parent progress capture من UID/install الحاليين؛ لا تعديل مخطط الأرشيف القديم أو إعادة نسبته.

القواعد المرشحة تتطلب session/users للحساب، install الحالي، originalId canonical ذي6أحرف، users.sharePersonalId مطابقاً، ومسار personal نشطاً يطابق حساب مالكه، وparent progress capture بنفس الحساب/UID/install. createdAt خادمي. التعديل والحذف ممنوعان؛ نفس الحساب يستطيع get/list، والحساب الآخر/غير المصادق لا يستطيعان ذلك. لا سماح قراءة أو تعديل جديد لـshare_ids أو للمحافظ/المقتنيات. تحقق مسار المعرف يتم داخل قواعد CREATE ذرّياً، وليس بعلامة من الهاتف.

## الربط مع المراجعة

أضيف `purchase-evidence.cjs`، ومجموعة IDs مشتركة فقط مع parser في purchase-frames.cjs (مطابقتها للـCheckout الأصلي وDart مفحوصة). يرفض parser المفقود وJSON التالف/المكرر والحقول/الأنواع غير المدعومة وتعارض أصل النسخة أو parent، ولا يحوّل paid إلى إيصال. يربط SHA256 النص الخام والحساب وoriginalId وcapture IDs وUID/install ووقت الخادم.

أصبح saveLegacyOperationReview يقبل purchaseCaptureId اختيارياً، ويقرأ النسخة في المعاملة نفسها قبل تقريره. لكل إطار: paid-recorded أو charging-recorded أو absent-on-source أو unexpected-value أو not-captured. بقاء paid مع إيصال قديم لا يحسم محاولة خصم native منفصلة. تبقى canProvePayment=false وcanAutoSettle=false وpendingPurchases=unknown، ولا خصم/رد/حذف pending أو ملكية جديدة. غياب سجل من جهاز جديد لا يثبت أن الجهاز القديم لم يشترِ شيئاً.
