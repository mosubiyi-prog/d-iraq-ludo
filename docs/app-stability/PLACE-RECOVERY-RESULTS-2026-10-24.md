## السلوك المتصل بالتطبيق فعلاً

عند فقد معرّف المكان المحلي في هاتف بديل، يستدعي Backend الأصلي في المصدر المولَّد قارئ DedaPublishedPlaceRecovery الجديد، خلف علم المصادقة المعطّل افتراضياً. لا يكفي اسم/هاتف محلي أو ظهور مكان عام بالخريطة. يلزم مستخدم SDK مجهول قائم، ورقم تثبيت قائم لا يُنشأ خلال الاسترجاع، ووثيقتا deda_sessions/users من Source.server، دون cache أو pending writes، وبنفس الحساب وUID والتثبيت.

بعد الإثبات فقط يُنفذ استعلام Source.server للحساب نفسه وpublished==true بحد سجلين. نتيجة الكاش، حتى الفارغة، ليست غياباً مؤكداً. تعدد الأماكن أو سجل غير مطابق أو تبدل هوية/جيل SDK/نية الحساب يرفض الاسترجاع. يعاد معرّف وثيقة المكان الحقيقي مع البيانات الأصلية؛ لا تسمح قيمة id داخل البيانات بتغيير المسار. لا كتابة مكان جديد، ولا استبدال ownerUid أو رقم الاعتماد، ولا منح دور أو إعادة PIN أو تبديل جلسة.

صفحة إدارة المكان مربوطة بفحص SDK وجيل اختيار الحساب طوال تحميل الحالة. حُرست أيضاً الانتظارات داخل ترحيل المفاتيح القديمة وقراءة المسودة وتنظيف حالة الحذف، فلا يستعمل مساعد متأخر حساباً آخر بعد تبدّل السياق. معرّف المكان المسترجع يُحفظ في المفتاح الملتقط للحساب الأصلي، وتُفحص نتيجة الحفظ قبل اعتماده في ذاكرة الصفحة. الانشغال/الفشل يبقي الحالة recovery_blocked مع رسالة تحديث؛ لا ينفذ دخولاً تصحيحياً.

تحديث إحصاءات التفاعل اختياري، فُنقل إلى afterSuccess بتصريح فحص جديد حتى لا يُبطل بطء العدّادات تحميل مكان تم التحقق منه. لم تُعدّل مصادر العملات أو المكافآت أو صلاحيات الإدارة العامة أو القواعد الحية أو التوقيع أو أرشيف100380.

## نطاق الفحوص

فحوص القارئ تغطي هوية SDK الجديدة مع بقاء ownerUid القديم، وربط التثبيت/users/session، والكاش/الكتابات المعلقة/الغياب، والنتائج المتعددة/غير المطابقة، وأخطاء النقل، والتبدل A→B→A أثناء كل انتظار. هناك widget test لصفحة OwnerPlacePage الأصلية عند انشغال المنظم، وفحص مصدر يثبت ربط Backend والصفحة بالقارئ، وفحص مدخل Backend الحقيقي ضد تجاوز مسار مشغول.

امتد harness Android المعزول من13 حالة جلسات إلى20:13 سابقة +7 للمكان. حسابا العميل ينشآن إثباتاتهما عبر DedaPinAuth وPIN الأصليين؛ لا زرع مميز لوثائق هويتهما أو دورهما. مكانان منشوران مصطنعان فقط قابلان للتهيئة/الإزالة بصلاحية الاختبار، لإعداد اعتماد سابق واختبار الالتباس. التقرير يصرّح بهذه fixtures، ولا يسميها بيانات عميل أصلية أو اعتماداً إدارياً حقيقياً.

الحالات الجديدة تتحقق من: منع الإدارة عند PIN خاطئ؛ استرجاع نفس المكان ورقم الاعتماد من UID جديد وتمكين تحديث التوفر بقواعد الخادم مع بقاء ownerUid القديم؛ رفض حساب آخر ومنعه من تحديث المكان أو منح نفسه إدارة عامة؛ رفض جلسة إدارة دون تغييرها؛ رفض الالتباس؛ واسترجاع المكان بعد إعادة العملية دون مسح بيانات الحزمة.

## ما لا تثبته هذه الدفعة

الهدف هنا مكان منشور معتمد عند غياب معرّفه المحلي، وليس استعادة كل حساب DEDA أو بياناته. لم يكتمل نقل النقاط/الذهب/XP/الماسات أو المفضلة أو الأماكن الشخصية أو المسودات غير المرسلة. الأماكن المخفية/غير المنشورة والطلبات المعلقة لها مسارات أخرى تحتاج قبولاً؛ استعلام published==true الفارغ لا يثبت عدم وجود تلك السجلات.

الاختبار يستخدم محاكي Android وجلسات/تثبيتاً جديداً، لا هاتفين فعليين، ولا واجهة إدارة ديدا كاملة بكل أفعالها. لا يثبت جاهزية فهارس الخادم الفعلية أو كل callables للتفاعل/الألوان. تحديث التوفر المقصود في الاختبار يحدث في سجل مصطنع داخل مشروع demo فقط. لم يحدث نشر أو تفعيل للمستخدمين أو تسليم APK موقعة. تبقى الاختبارات الحقيقية على الهاتفين والنسخة الموقعة والبيانات الأخرى ضمن CURRENT، ولا يجوز إعلان اكتمال المطلب كله بهذه النتيجة.
