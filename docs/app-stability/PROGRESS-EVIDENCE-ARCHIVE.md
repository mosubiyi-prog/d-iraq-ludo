# مخزن نسخ السجلات القديمة — مرشح معزول غير منشور

## ما نُفذ

مصدر الدفعة: `f7137459138e4c06c33068334ec9e011d66694a6`.

DedaProgressEvidenceStore يحفظ لقطة legacy للحساب داخل مسار مستقل `deda_progress_evidence/<accountKey>/captures/<captureId>`، ثم يعيد قراءتها من الخادم ويتحقق من المحتوى. يدعم قراءة لقطة قديمة واكتشاف قائمة محدودة من مرشحات الحساب، حتى مع UID وinstallId جديدين بعد الدخول الصحيح. لا استدعاءات من التطبيق أو حفظ فعلي لحسابات المستخدمين هنا؛ نقل Firebase محفوظ ومحلل، وفحوص Dart تستعمل IO مزيفاً.

القواعد في tools/app_stability/progress_archive/firestore.rules **مرشح كامل للمحاكي المعزول فقط، وليست بديلاً لقواعد التطبيق**. ملف firebase.json داخل المجلد يشغل Firestore المحلي على demo-deda-progress-archive. لا يوجد deploy في workflow الجديد ولا أسرار أو production project أو أثر APK. ملفات firestore.rules/firebase.json الأصلية في جذر المشروع لم تتغير.

## عقد الملكية والنسخة

| الجزء | الضمان المختبر وحدوده |
| --- | --- |
| ملكية الحساب | القواعد تتطلب deda_sessions/<uid> يطابق UID وaccountKey، وusers/<uid>.accountKey يطابق الحساب. إثبات الجلسة هنا مُجهز إدارياً في fixture المحاكي، وليس اختبار PIN أو قواعد إنشائه الحقيقية |
| إنشاء النسخة | sourceUid هو صاحب الطلب، installId يطابق جلسته، createdAt وقت الخادم، وcaptureId ثابت لنية الحفظ. البنية والحقول محصورة، ونوعها legacy-local-evidence |
| محتويات النسخة | ثلاثة نصوص محلية/غياب null فقط؛ تحفظ الصرف والمطالبات والنص التالف كما هو. SDK يحد كل نص بـ200000 بايت UTF8، والقواعد تحد size النص أيضاً؛ لا اقتطاع صامت |
| الإعادة | transaction تقرأ ID نفسه؛ المحتوى نفسه يرجع النسخة الموجودة دون كتابة، والمحتوى المختلف/المصدر المختلف تعارض. SDK قد يعيد تقييم callback داخلياً، وguard يفحص بعد القراءة وقبل set في كل تقييم |
| الحماية من المسح | العميل لا يحدّث ولا يحذف أي لقطة، حتى مالكها. اسم جديد يبقي التاريخ السابق. هذا يمنع overwrite من جهاز، ولا يثبت صحة أرقام legacy |
| جهاز جديد | المالك المثبت لنفس accountKey يقرأ اللقطة حتى لو كان sourceUid/installId من الجهاز القديم. حساب آخر أو ادعاء token role/account لا يكفي |
| فشل القراءة | cache/pendingWrites أو غياب/فساد/حساب مختلف لا يعاد كحالة صفرية ناجحة. فشل الحفظ لا يعاد تلقائياً بدالة خارجية |
| التنافس والمهلة | احتفظ بنفس captureId طوال النية وإعادة فتحها؛ تغيير ID لكل ضغط ليس منع تكرار. بعد dispatch قد يكتمل الأثر؛ guard/جيل SDK يمنع الخطوة التالية والنجاح المتأخر، ولا يدعي إلغاء كتابة أُرسلت |

النقل يستخدم Source.server وtransaction أصلية غير مغلفة بمهلة داخلية. عند الربط يجب أن يغطي isCurrent نية الحساب والمهلة، وأن تُراقب Future الأصلية حتى انتهائها، مع gate مشترك إذا كان الحفظ جزءاً من انتقال مصادقة. لا تعتمد انتهاء انتظار الواجهة دليلاً على فشل كتابة الخادم، ولا تعيد مكافأة بسببه.

## فرق الحفظ عن تطبيق التقدم

نتيجة read/list هي **دليل محلي محفوظ، لا رصيداً معتمداً**. لا يوجد هنا تحديث لمحفظة أو نقاط أو XP أو ملكية، ولا كتابة إلى SharedPreferences أو استعادة تلقائية. لا تمنح القواعد الجديدة أي حق صرف/زيادة عملة أو role/permissions. فحوص رفض محافظ أخرى تخص هذا المرشح المعزول ذي catch-all deny؛ لا تثبت أن دمجه مع القواعد الحية سيحافظ تلقائياً على كل سياسات التطبيق. يلزم فحص الدمج كاملاً لاحقاً.

createdAt يثبت وقت وصول اللقطة للخادم فقط. أحدث لقطة وصولاً قد تحمل بيانات جهاز قديم لم يصله صرف/تقدم لاحق؛ لا تطبق الأعلى/المجموع/الأحدث زمنياً كحل للمصالحة. القائمة (20 افتراضياً، 50 حد العميل) مرشحات تحتاج ترتيب أحداث/إصدارات معتمد، وليست اختيار الرصيد النهائي. معرّفات مطالبات محلية مختصرة لا تثبت عدم صرف مكافأة على جهاز آخر.

التقاط ثلاثة مفاتيح لا يجعلها معاملة واحدة لحدث المهام. الحساب القديم الذي فقد هاتفه قبل وجود نسخة خادم لا يمكن استعادة نصوصه غير المحفوظة بالاختلاق. هذه القطعة توفر وعاء حفظ وقراءة فقط؛ ربط تحديثات التقدم المستمرة وترحيل القديم بأمان وسياسة المصالحة مطلوبة لتحقيق شرط المستخدم فعلياً.

## الفحوص ومعناها

- مجموعة Dart: حفظ/readback، ID ثابت وتعارض، قراءة من UID/install جديد، قائمة محدودة، عدم قبول metadata محلية أو schema تالف، تبدل SDK A→B→A، نية منتهية قبل dispatch وبعده، وعدم اعتبار الفشل صفراً. النقل الفعلي مع plugin لم يُشغّل هنا.
- مجموعة قواعد Firestore Emulator: تحقق الملكية، وصول جهاز جديد، رفض الغريب/غير المسجل، الحقول المزيفة/المفرطة، ثبات اللقطة، معاملتان لنفس النية، والحدود المنفصلة للمحافظ والإدارة في المرشح.
- استعادة المصدر: --progress-evidence-store يضيف ستة modules مع تبعيات المالك/التقاط السجلات دون تغيير الملفات الأصلية أو إضافة قواعد/Android في مصدر Flutter المستعاد.

التشغيل المعتمد 40011805847 ناجح: 35/35 لمجموعة Dart، و37/37 لقواعد المحاكي، و16/16 لحماية الاستعادة، وجميع المجموعات السابقة ناجحة. التحليل الصارم للملفين الجديدين بلا ملاحظات. التفاصيل في CURRENT/RESULTS. الاختبار المحلي JavaScript تحقق صياغة، وPython تحقق حماية الاستعادة. لا نشر أو تحقق إنتاج أو فحص هاتف/تاب في هذه الدفعة.

## الخطوة التالية

صمّم مصالحة ذات مصدر موثوق للأحداث/الصرف والمكافأة وإصدارات الحساب، قبل أي تطبيق للقطات. افصل legacy غير المثبت عن دليل الحدث الحالي، واحفظ القديم دون تغيير. راجع القواعد المنشورة فعلياً وقواعد الدمج في محاكي قبل اقتراح تفعيلها. بعدها ربط محدود للحفظ/القراءة ودورة حياة التقدم مع عدم فقد التحديثات، ثم مقارنة جهازين وإعادة الفتح وضعف الشبكة. بقية بيانات التطبيق ومتطلبات الإدارة والمصادقة والنسخة الموقعة تبقى كما في CURRENT.
