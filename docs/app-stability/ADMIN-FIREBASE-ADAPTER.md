# محول دخول الإدارة — غير مفعّل

## نطاق التنفيذ ومصدره

`DedaAdminSessionFirebaseAdapter` يحرس تسلسل دخول الإدارة كاملاً بـgate المشترك مع المالك. `DedaFirebaseAdminSessionIo` يوفر نقل FirebaseAuth/Firestore/Messaging الفعلي عند إنشائه، ويستخدم مراقب SDK نفسه من IO المالك، مع hooks متزامنة مطلوبة لمسح وتدفئة كاش Backend الأصلي. لا يُنشئ التطبيق هذه الطبقات ولا يستدعيها في هذه الدفعة.

المصدر النهائي: `19423ff6460a6658f0bb9576540a3db6bdb7e514`. المقارنة مع Backend 100380 المستعاد ذي البصمة `7a1c35c1a6558d3286dd45f01831c17f9b37d48991c14dbb1346954240bb31d2`، لا ملف Backend القديم الخام في جذر المستودع.

| سلوك المصدر الأصلي | سلوك المحول المعزول |
| --- | --- |
| جاهزية Firebase ومسح الكاش قبل دخول SDK | نفس الترتيب، بعد قبول النية في gate فقط |
| البريد trim وكلمة المرور كما هي | محفوظان؛ لا مفاتيح دمج أو سجلات تتضمن بيانات الدخول |
| لا credential.user | false دون خطوات إضافية |
| سجل admins مفقود | خروج للجلسة الحالية فقط ثم false |
| active != true أو حالة غير active | خروج للجلسة الحالية فقط ثم admin-temporarily-stopped أو admin-disabled وفق normalizeAdminStatus الأصلي |
| اسم عرض اختياري | merge lastSeenAt/lastLoginAt فقط إذا الاسم فارغ؛ إضافة displayName/updatedAt فقط إذا غير فارغ |
| FCM ثانوي | فشل الإذن أو token أو كتابته لا يكرر المصادقة أو يحول الدخول المؤكد إلى فشل؛ token null لا يكتب |
| تدقيق ثانوي | admin_signed_in بنفس adminUid/adminName/adminRole/createdAt؛ فشل القراءة أو الإضافة لا يكرر الدخول أو ينهيه |
| currentAdminProfile قبل التدقيق | قراءة admins من الخادم، وتطبيع نفس حقول الملف والدور والحالة، ثم hook متزامن لتدفئة نفس كاش Backend قبل audit.add |

## فرق مقصود عن النموذج العام السابق

نموذج adminLogin في `DedaSessionFlowPrototype` كان اختبار عقد عام يعيد نتيجة typed ويرفض proof ناقص الدور، ويعيد خطأ audit. **ليس بديلاً مطابقاً لـBackend.signInAdmin.** المحول الجديد مستقل عنه لأن المصدر الفعلي يعيد bool، وله حالات false وأخطاء status محددة، ويبتلع أخطاء audit، ويستعمل normalizeAdminRole/status الحاليين. لا توصل نموذج الإدارة العام بشاشة الإنتاج.

لا ينشئ المحول دوراً أو صلاحية، ولا يكتب active/status/role/permissions أو admin_entry_access. تطبيع الدور الأصلي، بما فيه توافق الأسماء القديمة، يستعمل دوال Backend العامة النقية نفسها ولا يُعاد اختراعه. نجاح bool لا يثبت ملكية بوابة الإدارة ولا يمنح أي صلاحية جديدة.

## الأيقونة وتخويل الهاتف — حدود منفصلة إلزامية

main 100380 يبدأ `_adminEntryVisible = false`، ويستدعي currentDedaAccountCanSeeAdminEntry. المصدر يعتمد سجلاً صريحاً في admin_entry_access للهاتف الحالي، ويغلق الظهور عند الفشل. بعد دخول الإدارة يبقى currentAdminSessionMatchesDedaEntry مطلوباً للتحقق من ارتباط الهاتف بهذه الهوية/الدور. بوابة المدير العام والإضافة/الحذف والدعوات وقواعد الخادم تبقى كما هي، ولم يكتبها المحول أو يغير main/Backend.

**لا تستبدل شرط الأيقونة بنتيجة signIn أو بمجرد وجود SDK user أو كاش.** اختبار الاستعادة يقارن main/Backend/PinAuth بالبايت، لكنه ليس اختبار UI حي أو إثبات قواعد منشورة. ربط مراقبة الأيقونة وإبطالها عند تبديل حساب DEDA أو فقد التخويل ما زال يحتاج فحص دورة حياة مستقل؛ لا تكفي هذه الدفعة لإعلان اكتماله.

currentDedaAccountCanSeeAdminEntry القديم نفسه قد يستعيد جلسة مالك مجهولة. ذلك مسار تغيير جلسة يحتاج الربط المتناسق لاحقاً، وليس قراءة نقية ولا سبباً لتجاوزه أو حذفه. currentAdminSessionMatchesDedaEntry يحتوي self-heal لعضو مطابق البريد؛ يبقى تصنيف كتابة يحتاج permit نفسه قبل تشغيله، ولا يغلف بمنسق قراءة يعيد المحاولة.

## حراسة الانتظار والآثار الثانوية

تُقرأ proof الأولى من الخادم فقط، ويرفض cache/pendingWrites. لا خروج تنظيف عند خطأ قراءة أو مهلة أو إثبات قديم؛ الخروج للمفقود/الموقوف يفحص UID/نوع/جيل SDK قبل الإرسال. لا يمكن إلغاء signOut أُرسل فعلاً أو جعل Firebase خروجاً شرطياً ذرياً.

الإذن ثم token ثم كتابته خطوات منفصلة؛ يفحص التصريح والمستخدم بعد كل await وقبل الكتابة التالية. التدقيق يقرأ هوية الفاعل مجدداً قبل كاشه وكتابته؛ لا ينسخ كاش UID آخر. فشل خطوة ثانوية يُبتلع وفق المصدر الأصلي، ثم يُعاد فحص permit والمستخدم كي لا يخفي timeout أو تبدلاً. انتهاء مهلة UI يحتفظ بالقفل حتى تنتهي Future الحية، مع مراقبة الخطأ المتأخر ودون retry/rollback تلقائي.

إذا أُلغي تخويل المدير بعد proof الأولى أثناء الإشعارات، تتوقف هوية التدقيق إن كشفته القراءة التالية، لكن bool الدخول يبقى مطابقاً لعقد المصدر الأصلي؛ **هذا ليس إجازة إظهار الأيقونة أو تنفيذ عمل إداري**. فحوص التخويل المستقلة وقواعد الخادم مطلوبة في كل عمل كما كانت.

## امتداد شاشة الدخول — باقٍ قبل التفعيل

مراجعة admin_pages.dart في 100380 أثبتت أن Backend.signInAdmin يتبعه _saveIdentity ثم currentAdminProfile ثم currentAdminSessionMatchesDedaEntry. رفض المطابقة يستدعي signOutAdmin؛ ومسار mustChangePassword يعرض تغيير كلمة مرور وقد ينهي الجلسة عند الإلغاء. شاشة الدعوة أيضاً تطابق الهاتف بعد التفعيل ثم قد تخرج.

هذه الخطوات **لم تربط بعد**. لا تستبدل Backend.signInAdmin باستدعاء signIn المنفرد ثم تترك المطابقة والخروج القديمين خارج القفل. المدخل signInWithPermit ينفذ تدفق Backend بالتصريح الموروث دون gate جديد، كي تستطيع طبقة التنسيق المستقبلية إحاطة مرحلة المطابقة وآثارها المتناسقة. فحص محاكاة يؤكد بقاء القفل بيد التدفق الأب بعد اكتمال الدخول أثناء انتظار مطابقة تجريبية؛ هذا ليس تنفيذ قراءة السجل الفعلي.

يلزم حراسة حفظ الهوية المحلي والمطابقة/self-heal والخروج بالتصريح وجيل المستخدم، وتصميم انتقال مستقل لإرسال كلمة المرور بعد انتظار المستخدم مع إعادة تحقق الجلسة والتخويل. لا تُبقِ قفل SDK حياً خلال حوار إدخال مفتوح بلا حد، ولا تعتبر انتهاء مهلة الحوار إلغاء لتحديث كلمة مرور أُرسل فعلاً. لا تدخل gate مرة ثانية من داخل انتقاله.

## عقد الكاش والربط المستقبلي

hooks مسح/تدفئة الكاش مطلوبة صراحةً، لا بدائل no-op أو كاش موازٍ. ربطها المستقبلي ينفذ من داخل Backend حيث الحقول الخاصة متاحة، ويحدّث _cachedAdminProfile/_cachedAdminUid/_cachedAdminAt بشكل متزامن بعد تحقق المستخدم، مع بقاء TTL الأصلي 45 ثانية وقواعد الخادم مرجعاً للكتابات. لا تمرر مساعد Backend async القديم للإشعارات/التدقيق كما هو، لأنه يحتوي await قبل آثار تحتاج فحص permit.

أنشئ النقل بعميل FirebaseAuth المشترك وFirestore/Messaging من التطبيق نفسه. شارك gate واحداً، ومراقب SDK واحداً، ولا تُبطل النية بسبب إشعار الدخول المتوقع. يميز isCurrent نية الشاشة وحساب DEDA حتى لو بقي UID المجهول نفسه. لا تبدأ هذا الربط بينما مسارات SDK الأخرى خارج التنظيم.

## الحدود والمتبقي

`--admin-firebase-adapter` يضيف خمسة modules فقط مع تبعيات المالك. لا يغير اللقطة أو main/Backend/PinAuth أو Android أو التوقيع أو الحزم أو القواعد. لا APK/AAB أو نشر أو حسابات فعلية. الفحوص تستعمل DedaAdminSessionIo مزيفاً، وSDK/FCM/Firestore الحقيقي لم يُشغّل هنا؛ طبقة النقل تخضع للتحليل الصارم فقط. القواعد المنشورة والتكامل والأجهزة باقية.

التالي سلاسل الدعوات وإنشاء/تحديث بيانات الإدارة والخروج، وبقية مسارات المالك، ومطابقة بوابة الهاتف وتحديثاتها مع التصريح. بعدها اختبار التكامل المتناسق قبل تفعيل تجريبي محدود. التشغيل المعتمد 40007457858 ناجح في الأوضاع الثلاثة: 43/43 للمجموعة الجديدة و14/14 للاستعادة لكل وضع، وبقية المجموعات السابقة ناجحة. التحليل الصارم للملفين المحددين بلا ملاحظات. التفاصيل في CURRENT وRESULTS؛ لا نسبة إنجاز شاملة أو تحسن أداء هاتف بهذه المحاكاة.
