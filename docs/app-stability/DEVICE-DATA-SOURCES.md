## أول قطعة تنفيذ لحفظ الدليل المحلي

`DedaLegacyProgressReader` يلتقط **ثلاثة مفاتيح فقط**: task_points وsocial_progress وdiamonds_wallet أعلاه. النقل الأصلي SharedPreferences قراءة فقط؛ لا main callsites أو UI أو Firebase. الخيار --legacy-progress-capture يضيف module واحداً إلى مصدر الفحص فقط.

اللقطة تحفظ نصوص JSON الأصلية حرفياً، بما فيها الصرف والحجوزات ومعرفات المطالبة والبيانات التالفة. null يعني المفتاح غير موجود؛ المفتاح الغائب في استجابة تخزين ناقصة خطأ، وليس رصيداً صفراً. wrong native preference type يفشل دون استبدال القيمة القديمة. لا يمر أي installId أو PIN أو مفاتيح جلسات أو حساب آخر عبر قائمة المفاتيح؛ لا تُطبع محتويات اللقطة أو تُرفع في السجلات.

encode/decode أداة حفظ شكل فقط. يفحص فك الترميز نفس accountKey والبنية والإصدار، لكن **اللقطة دليل محلي غير موثوق وليست إثباتاً للرصيد أو المكافأة أو الملكية**. لا توجد دالة تطبيق/استعادة/دمج أو رفع للخادم أو صرف. ليست نسخة احتياطية منشورة للمستخدمين؛ لم يبدأ التطبيق بالتقاط بياناتهم أو حفظها سحابياً بهذه الإضافة.

القراءة تحفظ القيم الموجودة وقت الالتقاط، ولا تجعل تحديثات المفاتيح الثلاثة معاملة واحدة. قد يكون حدث قد حدّث ملف النقاط وينتظر تحديث XP/الذهب. يلزم عند الربط تنسيق انتهاء الأحداث الجارية أو سجل إصدار/أحداث موثوق؛ لا تعتبر التقاط ثلاثة نصوص إثبات اتساق حدث كامل. استعمل accountKey الحالي المثبت للخادم، ولا تغيّر صيغة الهاتف أو مفاتيح السجلات القديمة تلقائياً أثناء الترحيل.

يحتاج isCurrent جيل نية الحساب الذي يكشف A→B→A؛ تطابق رقم الهاتف النهائي وحده لا يكفي. القارئ يرفض النتيجة بعد تبدل النية أثناء تحميل التفضيلات. يلزم ربطه بإثبات الحساب ودورة حياته عند مرحلة الاستعمال.

## المعالجة التالية المحددة

صمّم مخزن حفظ/استرجاع خادمي للحساب وآلية مصالحة للإصدارات والأحداث بعد إثبات المالك، مع فصل المكونات المحلية عن أرصدة الخادم. ابدأ بفحص قواعد مرشح مع Emulator دون نشر، واحفظ نسخة الدليل القديم قبل أي ترحيل فعلي. لا تحوّل اللقطة غير الموثوقة إلى رصيد spendable، ولا تقبل max أو sum كحل لصرف وقع على جهاز آخر، ولا تعتمد الوقت المحلي وحده لتحديد النسخة الأحدث.

تحتاج السجلات المحلية القديمة خطة انتقال وحفظ معلّقة إلى أن تُحدّد سياسة التحقق وتُختبر؛ حفظ أحداث مستقبلية بخادم موثوق لا يثبت تلقائياً صحة كل تاريخ محلي سابق. كذلك حدود claims المختصرة محلياً لا تكفي وحدها لمنع إعادة مكافأة من جهاز جديد. لا تمسح القديم أو تعيد منح مكافآت أو تغيّر الرصيد أثناء هذا التصميم.

بعد ذلك ربط محدود يحافظ على البيانات القديمة عند فشل الشبكة، ويعرض غياب استعادة مؤكدة كحالة تحميل/تعذر مناسبة، ثم مقارنة جهازين بكل الحقول في DEVICE-CONTINUITY. متبقي الإدارة والخطة الأساسية يستمر كما في CURRENT. نتائج الفحوص تُعتمد من CI، ولا يوجد تحسن أداء أو استرجاع كامل مثبت من وجود هذه الوحدة.
