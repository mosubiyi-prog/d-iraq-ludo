# قياس بدء DEDA — ربط اختياري مع المصدر المرجعي

هذا دليل تجهيز القياس، وليس تقرير سرعة جهاز أو وعد تحسن أداء. مصدر الدفعة النهائي `6cde83e538347d30c458659f2cac6f6d6c5175d3`. تصحيح صياغة اختبار مراقب الإطار فقط: `c8e2398e91aa204c6e9a1e181b3df0a30ba9ba3b`. نقطة الرجوع السابقة `d1c7c937aefa3c0d524f602ac40e1fe1a254669f`.

## ما يقاس

الزمن يعتمد `Stopwatch` أحادي الاتجاه، بوحدة microseconds. يبدأ داخل مسار Dart في main؛ لا يشمل إنشاء عملية Android أو تحميل المحرك قبل دخول Dart. لكل خطوة حالة `pending` أو `succeeded` أو `failed` ومدة؛ الخطوات التي لم تبدأ لا تُسجل كأنها نجحت. المفاتيح ثابتة من enum ولا تقبل أسماء مستخدمين أو عمليات مخصصة.

| اسم القياس | المعنى |
| --- | --- |
| `bindings` | استدعاء `WidgetsFlutterBinding.ensureInitialized` |
| `mapCache` | إنشاء مزود ذاكرة خرائط OSM الحالي بحجم 128MiB |
| `firebase` | انتظار `Firebase.initializeApp` |
| `preferences` | انتظار `DedaPreferences.load` |
| `tasks` | انتظار `DedaTaskEngine.initializeForCurrentAccount`، حتى اكتمال الجزء الذي ينتظره main |
| `launch` | استدعاء `runApp`، لا اكتمال تحميل الواجهة |
| `firstFrame` | انتظار callback مسجل عبر `addPostFrameCallback` قبل launch مباشرة كي يلتقط إطار warm-up أيضاً |

`bootElapsedMicros` يقيس حتى عودة مسار التهيئة، و`firstFrameFromBootMicros` حتى callback الإطار. لا تفسر post-frame بأنه قياس اكتمال الرسم على GPU أو تحميل الخرائط والأقسام أو صلاحيات الجلسة. إذا لم يصل callback يبقى قياس الإطار pending وتبقى مدة أول إطار null. استدعاء callback مرتين لا يغير أول نتيجة.

تحديث مكافأة المدير الشبكي داخل TaskEngine يعمل أصلًا دون انتظار عبر `unawaited`؛ لا يشمل قياس tasks انتظار اكتماله، ولا يعد اكتمال tasks إثباتًا لجاهزية الإدارة.

## الحفاظ على السلوك

يبقى الترتيب تسلسليًا كما في المصدر المرجعي. فشل Firebase يسجل failed ويكمل التفضيلات والمهام، لأن main الأصلي يتسامح معه. أخطاء التهيئة الأخرى تنتقل كما هي وتوقف الخطوات اللاحقة. القياس لا يضيف timeout أو إعادة محاولة أو تسجيل دخول أو خوادم. فشل تسجيل مراقب تشخيص الإطار لا يمنع تشغيل الواجهة. ربط المراقب قبل launch مباشرة لا يغير ترتيب استدعاءات التهيئة الأصلية؛ زمن firstFrame يشمل استدعاء launch وانتظار الإطار. فشل launch يلغي انتظار الإطار بدل إبقائه pending.

عند إغلاق العلم يبقى جسم main المرجعي نفسه داخل الفرع غير المقاس، مع اختلاف إزاحة النص فقط. الاختبار النصي يتحقق من بقاء الجسم كاملًا، ولا يكتفي بوجود أسماء الدوال. أداة الربط ترفض main لا يطابق بصمة المرجع، وترفض تطبيق الربط مرتين.

## التفعيل للمراجعة المستقبلية فقط

1. استعد المصدر إلى مجلد عمل منفصل فارغ: `python3 tools/restore_deda_stability_baseline.py <empty-output> --startup-metrics`. أضف `--pilot` فقط إن أردت تجربة الهوية كذلك.
2. المصدر المقاس يتطلب `--dart-define=DEDA_STABILITY_STARTUP_METRICS=true`. دون العلم ينفذ فرع main الأصلي. علم تجربة الهوية مستقل عنه.
3. snapshot متاح للمطور محليًا عبر `dedaStartupMeasurements.snapshot`. لم تضف هذه الدفعة واجهة تشخيص للمستخدم أو تصديرًا أو إرسالًا تلقائيًا.

كلا العلمين false افتراضيًا. workflows النسخ السابقة وإعدادات Android والتوقيع والـarchive المرجعي لم تتغير. وجود module داخل المستودع أو تمرير العلم وحده إلى workflow قديم لا يربط main تلقائيًا؛ يلزم المصدر المستعاد بالاختيار أعلاه. لا تنتج هذه الدفعة APK.

## خصوصية وحدود الفحص

snapshot في الذاكرة، بلا هاتف أو UID أو PIN أو موقع أو نتيجة جلسة أو نص خطأ. لا كتابة إلى ملف أو Firebase أو analytics، ولا طباعة تلقائية. الخرائط المتداخلة في snapshot غير قابلة للتعديل.

الفحوص الزمنية الحتمية تستخدم ساعة وأعمال تهيئة مزيفة؛ أرقامها تتحقق من صحة العداد ولا تصف أداء Android. يوجد أيضًا فحص Widget بسيط لمراقب إطار Flutter، دون Firebase أو حساب حقيقي. فحص bootstrap الحقيقي على الهاتف، وأزمنة SDK والشبكة والجهاز ونسب التحسن قبل/بعد ما زالت مطلوبة.

بعد اكتمال بقية الربط وتجهيز نسخة فحص: اجمع عدة قراءات بدء بارد وإعادة فتح لكل نسخة على حدة، على الجهاز نفسه وبأداة القياس نفسها وظروف شبكة متقاربة. استخدم القياس نفسه للمصدر المرجعي ومصدر التجربة حتى لا تنسب كلفة أداة القياس إلى فرق التطوير. سجل وضع الشبكة خارج snapshot دون بيانات حساب. قارن وسيط عدة محاولات لكل وضع؛ لا تنسب الفرق من محاولة واحدة لتحسين كود. لا تستخدم زمن CI أو الساعة المزيفة بوصفه زمن الهاتف.
