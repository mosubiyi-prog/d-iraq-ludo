# محول Firebase للمالك — محفوظ وغير مربوط بالتطبيق

مصدر المحول بعد تصحيح تركيب النقل: `62fc95b132031c1a81d0225e2cad0f1e64869eb1`.

## حدود التنفيذ

`DedaOwnerSessionFirebasePort` ينفذ جانب المالك من عقد نموذج التدفق. `DedaFirebaseOwnerSessionIo` يستخدم FirebaseAuth وFirestore وSharedPreferences الحقيقيين عند إنشائه، لكن لا ينشئه main أو Backend أو PinAuth في هذه المرحلة. الفحص يستبدل نقل SDK/الخادم بمزيف، ويختبر خيارات النقل والتفضيلات المحلية بمضاعفات اختبار عبر المنشئ forTesting، دون الاتصال بحساب أو خادم.

الإدارة غير مدعومة بهذا المحول: استدعاء دخول الإدارة يفشل UnsupportedError قبل أي عملية SDK. نموذج الإدارة السابق ما زال اختبار عقد فقط. لا تستخدم محول المالك مكان Backend.signInAdmin.

`--owner-firebase-port` يضيف أربعة ملفات معزولة: gate والنموذج ومراقب جيل SDK ومحول المالك. لا يغير main أو PinAuth أو Backend، ولا يضيف Android. حتى العلم وحده لا يفعّل الربط؛ لا توجد callsites إنتاج لهذه الملفات.

## دليل القواعد وحدوده

راجعت نسختي قواعد المستودع فقط. بصمة firestore.rules: `a79931017197a1895fd19f9d14c2455e621b2e12dc520102b911d9007d55721e`، وfirestore.spark.qa.rules: `3ad37e9eb911a301f5b418736410ddab61db5d909e1de23dc956e20049009d56`.

فيهما قراءة deda_auth_attempts ممنوعة؛ لا يحاول المحول قراءتها. جلسة UID يقرؤها صاحب SDK نفسه، وكتابتها تحتاج إثبات PIN أو عضوية installId موثوقة. profile يُقرأ بملكية الجلسة أو المدير العام. إثبات المحول يعتمد نجاح كتابة أقرّها الخادم ثم readback من الخادم؛ الإيصال المحلي وحده لا يجيز ملكية. لا يمنح هذا إثبات شراء أو رصيد أو معرّف مميز.

**لم تُقرأ القواعد المنشورة الحية في هذه الدفعة، ولم يُختبر هذا المحول مع Emulator أو Firebase فعلي.** بصمات الملفات ليست إثباتاً أنها القواعد المنشورة. يلزم اختبار التكامل بالقواعد المعتمدة قبل إنشاء أي نسخة تفعل المصادقة الجديدة. لا تعديل أو نشر قواعد ضمن هذه الدفعة.

## أجيال SDK والمهلة

شارك IO واحداً لكل FirebaseAuth وgate واحداً بين تدفقات المالك والإدارة عند تصميم الربط. مراقب authStateChanges يزيد جيل SDK عند تغير UID أو نوعه، بما فيه A→B→A، ويتجاهل الإشعار المطابق. القراءة المتزامنة لـcurrentUser تطابق أيضاً الحالة الفعلية. الإشعارات المتأخرة قد ترفض انتقالاً بحذر؛ يلزم فحص ترتيب إشعارات SDK الحقيقي قبل التفعيل. فشل المراقبة أو انتهاؤها يجعل النقل غير جاهز، والتخلص منه يوقف اشتراكه.

لا timeout داخلي حول Future تسجيل الدخول أو الكتابة. مهلة gate تنهي انتظار الواجهة وتحجز المسار حتى تنتهي Future الأصلية. بعد كل await يُفحص التصريح وUID/نوع/جيل SDK قبل الأثر التالي. signOutIfCurrent يفحص المستخدم قبل dispatch بلا await بينهما، لكنه لا يدعي أن SDK signOut ذري مشروط أو قابل للإلغاء. أثر أُرسل فعلاً قد يكتمل بعد المهلة أو تبدل خارجي.

## ما بقي قبل الربط

المحول مخصص لدخول مالك قائم واستعادته فقط. إنشاء الحساب، accountExists وتجهيز جلساته، الاسترداد وmarkCurrentDeviceTrusted، ومسارات Backend الأخرى ما زالت غير منظمة بهذا المحول. لا تضف timeout+retry حول هذه الدوال ولا تدعِ حماية كل المصادقة. يلزم حفظ قفل PIN المحلي وسياسة أخطاء الواجهة وتفضيلات الجلسة عند اختيار callsites.

التالي بناء محول الإدارة مع المحافظة على clearAdminProfileCache وnormalizeAdminStatus/نتائج الخطأ وdisplayName الاختياري والإشعارات والتدقيق، ثم سلاسل الدعوات وتغيير البيانات والخروج. قبل ربط الإنتاج تُراجع جميع مسارات SDK الأصلية كي لا تعمل بالتوازي خارج القفل. لا تكفي إضافة gate حول primitive واحد.
