## التنفيذ الحقيقي ضمن الاختبار المعزول
- `functions/deda_logical_room_offline_preflight_PRIVATE_NOT_EXPORTED.js`: وصف خطط المجالات الأربعة عشر، جميع قرارات الوصول والتعديل والفوترة والإدارة تظل `false`، ولا تقبل بيانات العميل كإثبات شخصي.
- `functions/deda_logical_room_domain_readback_OFFLINE_ONLY.js`: قراءة شكلية من بيانات اختبار خيالية لصداقات UID pair، وإيصالات الهدايا، محفظة الهدايا، اختيار الآيدي المميز والدوري، مع منع احتساب الرصيد أو منح الجوائز. لا يتصل بقاعدة بيانات.
- معالجة حالة مهمة: إذا ظهر نفس الصديق الخارجي ضمن سجلات هويتين تاريخيتين من A/B/C، يُسجل `ALIAS_FRIEND_DUPLICATE_REVIEW_REQUIRED` **بدون دمج أو إنشاء دعوة**.
- معالجة حالة علاقة بين اثنين من A/B/C: تُسجل `INTERNAL_ALIAS_RELATION_REVIEW_REQUIRED`، بدلاً من اعتبارها صديقاً جديداً أو حذفها تلقائياً.
- تشديد مصدر سجلات الأصدقاء والهدايا إلى `cached === false` و`pendingWrites === false` في نموذج الاختبار؛ نقص بيانات الحداثة يمنع أي حكم شكلي. هذه الأعلام *ليست* بمفردها شهادة ملكية مستقلة.
- سجل دوري أسبوعي بدون سجل ربط حساب، أو بدون بيان تحكم الأسبوع، لا يُحسب كنقاط صفر أو جوائز مستحقة. `LEAGUE_CONTROL_MISSING_HISTORICAL_UNKNOWN` عند غياب مصدر الأسبوع مع بقاء ربط الحساب.

## الفحص المثبت
- أُعيد تحميل الشيفرة والاختبارات من **فرع GitHub بعد حفظها** وتنفيذ 3 مجموعات اختبار مكونة من **67 حالة إجمالاً، 67 نجاحاً، صفر فشل** في V8 مع بديل محلي لـ `node:test` و`assert`.
- المجموعات: 18 فحص الغرفة الأولي + 33 فحص مصادر الأقسام بعد إضافة 7 حالات جديدة + 16 فحص حارس إثبات الملكية الأصلي.
- **ليس** تشغيل `node --test` الأصلي ولا Firebase Emulator، ولا اتصالاً حياً ولا فحص هاتف. نتيجة النجاح محصورة في سلوك الدوال المعزولة داخل بيئة V8.
- مقارنة GitHub بمرجع المصدر: 4 ملفات JavaScript مضافة تحت `functions/` (ملفا محاكاة وملفا اختبار) قبل هذه الوثيقة، ولا تغيّر `functions/index.js` ولا أي ملف Flutter أو `firestore.rules`.
- لا استدعاء Firebase/Admin/Auth أو Firestore أو شبكة أو كتابة قاعدة بيانات ضمن الوحدتين. استخدام `Map.set` الذاكرية في معالجة تكرار الأصدقاء **ليس** عملية كتابة إلى Firestore.
- لا حذف، دمج، نقل UID، إنشاء UID، إنشاء token، تغيير PIN، منح إدارة، صرف ماسات، إعادة إصدار هدايا، أو نشر Play.

## الأقسام والمخاطر المتبقية
- `A/B/C` تبقى مفاتيح تاريخية مستقلة؛ `D` أو أي جلسة مجهولة لا تصبح مالكة لحقوقها.
- حل التكرار عرضاً أو فعلياً للأصدقاء يحتاج تفويضاً وتحليلاً بحسب UID ومصدر السجل، لا مسح علاقات أو `pairKey`.
- الماسات والهدايا والمستوى والنقاط تحتاج Ledger موثوق وحق وصول نطاقي؛ missing لا تعني صفر، ولا تُجمع الأرقام تلقائياً.
- الإدارة تحتاج مصادقة `admins/{auth.uid}` مستقلة عن حساب المستخدم والمنطق الموحّد؛ عرض الزر لا يمنح الدور.
- لم يُفحص تكامل Flutter أو القواعد المنشورة أو السلوك على هواتف المستخدمين؛ ولم يثبت الدليل المستقل لملكية سجلات A/B/C أو جهة خادمية مفوضة لتنفيذ الربط الحقيقي.

## القرار
- **PASS** لإضافة فحص تعارض مصادر الأقسام والمحاكاة المحلية، مع اعتماد 67/67 حالة وهمية.
- **NO-GO / SAFE HOLD** لاسترجاع الحساب الحقيقي، تفويض القراءة بين UIDات تاريخية، تعديل Firestore/Auth/Rules، أو أي APK / Play. بحسب الوثيقة، الخطوة الثانية **قيد التطوير المعزول فقط، غير مكتملة** إلى حين استيفاء إثبات الملكية المستقل والتفويض الخادمي واختبارات الجهاز والتكامل.
- **الخطوة الثالثة لم تبدأ.** لا تُعتبر هذه الوثيقة نجاحاً للاسترجاع، وإنما دليل على نطاق الاختبار وحدوده.

## ملحق إصلاح عدم تطابق إيصالات هدايا الإدارة — 16 نوفمبر 2026
- **الثغرة المصدرية المعزولة:** فاحص `checkGifts` كان يفحص علاقة `giftId` بوثيقة الهدية في حالة `sourceType=weekly_league` فقط؛ فيما `firestore.rules:2307-2360` تشترط كذلك `giftId == document ID` و`amount <= 1000000` لهدايا الإدارة، مع انتقال `pending -> received` المرتبط بالرصيد.
- **الإصلاح على فرع الاختبار فقط:** تحقق صريح من `giftId` وحالة الهدية وحد 1,000,000 وحقول وقت الإنشاء/الاستلام **ببيانات اصطناعية**؛ الأنواع التاريخية المجهولة تُحفظ كمراجعة مطلوبة `UNKNOWN_GIFT_SOURCE_REVIEW_REQUIRED`، لا تُحسب رصيداً ولا تُحذف.
- **الفحص:** أُعيد تنزيل ملفات الاختبار الثلاثة الأصلية من GitHub بعد التحديث وتشغيل **73 حالة / 73 PASS** ببيئة V8 مع بديل `node:test`، لا Native Node ولا Firebase Emulator ولا اختبار إنتاجي. 6 حالات جديدة، بالمقارنة مع 67 سابقاً.
- **التحقق من أثر التعديل:** مقارنة فرع الاختبار مع `fd8cfd590d0f6703e34d6fe8c6913b091c3468fd` أظهرت إضافات معزولة فقط؛ `functions/index.js` لم يتغير، ولم يحدث تعديل لأي كود إصدار محمي أو قواعد Firebase أو بيانات مستخدم.
- **قرار الوثيقة المستمر:** `PASS` لإصلاح فاحص مصدر محلي تجريبي فقط؛ **NO-GO / SAFE HOLD** لأي منح وصول عابر للـUID أو استرجاع فعلي حتى يتم إثبات الملكية المستقل وفحص التكامل بإذن مناسب. الخطوة الثانية غير مكتملة، والثالثة لم تبدأ.

## ملحق اتساق مصادر المحفظة والآيدي المميز والدوري — 16 نوفمبر 2026
- **الخلل المعالَج في نموذج الاختبار:** كانت الدالة `checkFriends` ودالة `checkGifts` تشترطان `cached=false` و`pendingWrites=false` من صفوف المحاكاة، بينما `checkWallet` و`checkPremium` و`checkLeague` كانت تمنح صفة تطابق *شكلي* رغم غياب هاتين العلامتين.
