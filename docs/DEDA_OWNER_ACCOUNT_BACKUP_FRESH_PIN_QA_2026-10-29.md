# DEDA — حفظ أرشيف التقدم ومراجعته من هاتف ثانٍ (مُحاكي فقط) — 2026-10-29

## ما تم بناؤه
- تدقيق المصدر الحقيقي: `DedaProgressEvidenceStore` لديه فعلاً `save/read/list` لحفظ ثلاثة سجلات محلية تاريخية كاملة دون إعادة كتابة الأصل: نقاط المهام، XP والعملات الاجتماعية، والماسات. الميزة وراء `DEDA_STABILITY_PROGRESS_BACKUP_PILOT=false` في نسخة التطبيق المرجعية، ولا توجد صلاحيات لهذه المجموعة في `firestore.rules` الأصلية؛ لذلك لا يصح الادعاء بأن النقل يعمل حالياً.
- مرشح صلاحيات Firestore للاختبار فقط، يتم تركيبه آلياً مع القواعد الأصلية دون تعديلها. يسمح بحفظ **أرشيف غير موثوق غير قابل للتغيير** للحساب صاحب PIN حديث (10 دقائق) + جلسة Firebase + ملف مستخدم مطابق. هاتف ثانٍ بمعرّف Firebase مختلف يستطيع استعراض الأرشيف بعد PIN الصحيح. **المعرّف المثبت للهاتف وحده لا يكفي**.
- يرفض حذف الأرشيف وتحديثه ومضاعفة حقول السجل، انتحال المصدر والآيدي أو رقم الحساب، وتجاوز حد عرض القائمة، ومطالبات تكوين XP/ماسات.
- الاختبار يستخدم Firebase Authentication Emulator وFirestore Emulator الحقيقيين بحسابات وهمية وصيغة إنشاء الحساب والـPIN والجلسة الأصلية للتطبيق، دون استخدام أرقام أو أرصدة حقيقية.

## ما لم يُنجز ولا يجوز ادعاؤه
- **لم تتحول النسخة المؤرشفة إلى رصيد أو تقدم فعلي في الهاتف الثاني**. الاسترجاع الآمن يتطلب مصادقة خادمية قوية وتسوية القيم القديمة ووقف كتابة APK القديم لمنع التكرار.
- النموذج الأصلي للـPIN لا يملك نظاماً خادمياً قوياً للحد من التخمين. ومعرفة/نسخ install ID كانت كافية في اختبار سابق لتسجيل جلسة أصلية، لذا لا يمكن إطلاق هذه الصلاحيات المقترحة إلى الإنتاج. شرط PIN الطازج يحمي **الأرشيف المرشح فقط** ولا يعالج كل النظام.
- لا يوجد Firebase deployment ولا Android APK/AAB ولا نشر Play. النسخة 100342 وقواعد الإنتاج وبنك الأسئلة والماسات والإطارات والآيديات محفوظة، ومراجعة المالك مطلوبة قبل أي APK.
- بعد نجاح الفحص يأتي مسار دمج **مصادقة واستعادة الحساب** مع مراجعة صريحة لمصدر نقاط الدوري، ثم الربط النهائي للجوائز والواجهة والإدارة. تجنب اختراع أرصدة من البيانات القديمة؛ الأرشيف دليل للمراجعة وليس أمراً بالاسترجاع.
