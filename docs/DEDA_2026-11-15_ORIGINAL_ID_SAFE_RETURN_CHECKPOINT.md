# DEDA — نقطة توقف: الرجوع الآمن للآيدي الأصلي بعد المميز
**التاريخ:** 2026-11-15  
**الفرع المعزول:** `deda-original-id-verified-return-source-only-2026-11-15`  
**النطاق الوحيد:** إعادة إتاحة خيار استخدام المعرّف الأصلي المحفوظ حتى عند فشل/تأخر قراءة المعرّفات المميزة، دون فصل الهوية عن خادمها.

## الطلب والسبب
صاحب DEDA يريد الرجوع إلى آيديه الأصلي بعد استخدام الآيدي المميز ليرى هل يخف تأخير الملف الشخصي، مع الاحتفاظ بالمميز وملكيته والماسات وكل وظائف التطبيق.

فحص المصدر أثبت أن الأصل لا يزال محفوظاً؛ والخدمة تتضمن بالفعل `use(originalId, originalId)` لإعادة اختيار الأصل. لكن `DedaStage71OwnedIdsPanel` كان يؤخر عرض خيار الأصل حتى تنجح قراءة المقتنيات المميزة واختيار الآيدي النشط معاً. واجهة النسخة على الهاتف تُظهر كذلك `الملكية بانتظار التحقق من الخادم`، وهذا قد ينتج أيضاً من تعارض UID ويجب عدم تجاوزه.

## ما أُنجز
1. تحديث `lib/deda_stage71_free_owned_use_profile.dart`: فصل إثبات المالك الأصلي عن تحميل قائمة المميز وإظهار خيار الأصل بعد إثباته الخادمي، مع إخفاء المميز عند فشل إيصالاته.
2. حفظ مدخل آمن `verifyOriginalOwner` يُراجع نفس Firebase UID والمستندات `users/{uid}` و`deda_sessions/{uid}` و`deda_share_ids/{originalId}` عبر `Source.server` وسياسة `DedaQa32ManagerOriginalOwnerProof.authentic`. لا يقبل UID آخر أو جلسة مجهولة غير مثبتة.
3. لأن التجميع المحمي 100447 يستعمل طبقة Stage71 أقدم من المصدر الحالي، أُنشئ `tools/app_stability/app_package/bind_original_id_verified_return_20261115.py` لدمج تبديل الأصل في نسخة تجميع مؤقتة مع **عدم تغيير دالة Use الخادمية القائمة أو نشر الآيدي**. فحص UID يُعاد قبل عملية الاستخدام.
4. فحص مصدر محافظ `test/test_deda_stage71_original_return_owner_guard.py`، وفحص التجميع الكامل في `.github/workflows/deda-original-id-verified-return-source-qa.yml`.
