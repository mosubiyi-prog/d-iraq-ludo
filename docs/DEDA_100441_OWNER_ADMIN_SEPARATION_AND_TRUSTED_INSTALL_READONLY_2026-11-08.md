# DEDA 100441 — تدقيق فصل تخويل الإدارة عن انقسام هويات الحساب + قائمة الأجهزة الموثوقة

**التاريخ (العراق):** 2026-11-08  
**موافقة المدير العام:** «تمام باشر وستوفيني بالموجز» بعد توضيح أن حساب التابلت مختلف وأن حسابات الإدارة الثلاثة المفوّضة غير A/B/C.  
**الفرع المنعزل:** `deda-100440-session-rescue-isolated-owner-review-2026-11-07`  
**النتيجة:** فحص القراءة الحية ناجح؛ لا تغيير Firebase ولا APK ولا تصحيح UID.

## أدلة القراءة الفعلية

- [GitHub Actions 42421580232](https://github.com/mosubiyi-prog/d-iraq-ludo/actions/runs/42421580232): `SUCCESS`؛ `PASS_PRODUCTION_SOURCE_UNCHANGED`.
- السكربت `tools/deda_100441_admin_gateway_vs_owner_uid_abc_readonly_2026_11_08.py` يقرأ مسار الآيدي الأصلي المعروف من تدقيق سابق للمدير ثم حساب الرقم نفسه وA/B/C فقط، بلا سرد لأي حسابات أخرى أو قراءة PIN أو أرقام أجهزة أو بيانات إدارية حساسة.
- تأكيد أن A/B/C ثلاث هويات مختلفة مرتبطة بنفس حساب الرقم: **YES**.
- وجود بوابة `admin_entry_access/{accountKey}` **YES**، وتطابق `active=true`, `status=active`, `accessType=general_manager_gateway`, `allowedRole=general_manager` **YES**.
- `admins/{A}`: **غير موجود**.
- `admins/{B}`: **غير موجود**.
- `admins/{C}`: **غير موجود**.
- `deda_account_profiles/{accountKey}`: **موجود**، ويحتوي قائمة `trustedInstallIds` غير فارغة، لكن السكربت لا يطبع أو يعرض أي قيمة منها.
- لم يُفحص أو يُعدّل أي حساب إداري آخر. لا يمكن من هذا الفحص وحده إثبات وجود **ثلاثة** تخويلات أخرى بالعدد؛ يستلزم ذلك تدقيقاً مستقلاً مفوضاً وفي نطاق مختلف.

## تفسير معماري مثبت من المصدر

- `lib/deda_backend.dart` عند `currentDedaAccountCanSeeAdminEntry`: ظهور بطاقة الإدارة يحصل بعد توفر جلسة DEDA وقراءة بوابة `admin_entry_access/{accountKey}`، ولا يعني وجود جلسة إدارة.
- `lib/deda_backend.dart` عند `signInAdmin` و`currentUserIsAdmin`: صلاحيات الإدارة تعتمد على مصادقة Firebase غير مجهولة وعلى سجل `admins/{uid}` فعال؛ مجرد وجود بوابة رقم الحساب لا يمنح الصلاحيات.
- `firestore.rules` عند `isAdmin` و`isGeneralManager`: إثبات هوية الإدارة يتطلب وثيقة `admins/{request.auth.uid}` صالحة. لذلك A/B/C ليست ثلاث هويات المدير المعتمدة بحد ذاتها. بوابة الرقم ترخيص **مدخل واجهة** منفصل.
- `deda_account_profiles.trustedInstallIds` قائمة معرفات تثبيت قديمة ولا تمثل مفتاح جهاز غير قابل للاستخراج، ولا جملة challenge موقعة، ولا إثبات حيازة `Firebase Auth.uid=A`. **لا تُستخدم كعامل ملكية مستقل يكفي وحده لإصدار token أو نقل UID.**
- مستخدم التابلت حسب إفادة صاحب المشروع دخل **حساب DEDA آخر**؛ لا يجوز استعمال هوية التابلت لتفويض استرجاع الحساب الأول أو نقل إدارة.
- النسخة 100441 على الهاتف ما زالت تُظهر `FirebaseAuth.currentUser=null`، ما يفسر تعذر قراءة بوابة الإدارة من الحساب، **دون أن تكون هذه القراءة إثباتاً وحيداً للسبب**؛ لا توجد صلاحية لتغيير `admins` أو `admin_entry_access` بغرض إظهار البطاقة.

## قرار حماية المسار القادم

1. إبقاء الحسابات الإدارية الثلاثة المفوّضة **خارج حساب A/B/C وخارج أي انتقال هوية**؛ لا مساس بـ`admins` أو `admin_entry_access`.
2. انقسام الهوية الأصلية A/B/C ما زال يتطلب عامل ملكية موثوق مستقل عن PIN، أو مراجعة استرجاع مالك موثقة خارج التطبيق قبل إدخال تغيير خادمي محدد. القائمة القديمة `trustedInstallIds` **دليل حالة مساند** وليس عامل إثبات مستقل.
3. المرحلة التنفيذية التالية، عند توفر إثبات ملكية خارجي صريح: تجهيز قائمة تغييرات خادمية **محددة ومحدودة وقابلة للتراجع** لتصحيح ربط الرقم والجلسة مع ثبات الآيدي المميز، ثم اختبارات هاتف قبل أي تحديث مستخدمين. لا تبدأ تلك المرحلة الآن لأن إثبات ملكية A بالوسيلة المستقلة لم يكتمل.
4. لا تجربة PIN عبر المحادثة أو GitHub، ولا تسجيل دخول أو ربط Google/بريد أو إصدار custom token بالتخمين.
5. لا تغيير 100440/100441 أو Firebase أو قواعده أو محفظة الماسات/الهدايا أو إدارة الدوري أو الأصدقاء أو الأدوار.

**نقطة توقف:** تحقق فصل أذونات الإدارة ووجود قائمة أجهزة قديمة **مكتمل**، لكن ربط الهوية الأصلية وحساب الاسترجاع **غير مكتمل**. القرار التالي يجب أن يكون حول أدلة ملكية مستقلة موثوقة وليس تعديل Firebase العشوائي.
