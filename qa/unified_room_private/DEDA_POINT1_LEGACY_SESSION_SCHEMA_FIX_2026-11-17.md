# DEDA — نقطة 1: إصلاح تعارض جلسة الغرفة مع مخطط PIN التاريخي

**النطاق:** تشغيل ربط الغرفة الموحدة للأصدقاء والدوري والآيدي عبر جلسة واحدة بدون تشتت الهوية، ودون لمس إنتاج Firebase.

**مرجع الجولة:** `6ea510f69e9e00591193517a83f85183425d6dfd`
**آخر تعديل برمجي قبل الوثيقة:** `9a296f32600ff8203f6adb6e2167000f065aa393`.

## السبب الجذري المثبت
قواعد `firestore.rules` التاريخية تقبل في `deda_sessions/{uid}` حقول PIN الأصلية `uid/accountKey/installId/signedInAt/lastSeenAt`، بينما حارس الغرفة يتوقع `active/revision/sessionNonce/canonicalAccountId`. استخدام نفس المستند يمنع التوافق حتى مع مراجعة ملكية صالحة. لا يجوز تعديل مخطط PIN التاريخي عشوائياً بسبب نسخ Play القديمة.

## الإصلاح المصدري المنجز
- انتقال قراءة حارس الغرفة وخدمة إصدار التصاريح إلى **`deda_unified_room_sessions/{readerUid}`** منفصل، مع الإبقاء على `deda_sessions` التاريخي دون تغيير.
- تعديل قواعد Firestore المرشحة فقط لإلزام مطابقة revision/nonce ضمن مساحة جلسات الغرفة الجديدة ومنع العميل من قراءة أو كتابة سجلات الجلسة نفسها.
- إضافة خدمة bootstrap خاصة جديدة `functions/deda_unified_room_session_bootstrap_private_v1.js` تنشئ ذرياً سجل القارئ والجلسة والغرفة وسجل التدقيق **فقط بعد تحقق ملكية مستقل موثوق ومصادقة دائمة وحسم المصدر التاريخي A/B/C**. افتراضياً `enabled=false` ولا يوجد export لها في `functions/index.js`. لا تنشئ UID أو جلسة Firebase Auth ولا تعدل أي بيانات تاريخية أو أموال.
- تحديث اختبارات Node والمختبر لتثبت عدم تغيير جلسات PIN وسلوك Play، ورفض التصريح بعد تغيير revision ورفض غياب إثبات الملكية.
